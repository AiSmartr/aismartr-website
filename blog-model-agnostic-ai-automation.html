Model Prices Just Dropped 80%. Is Your Automation Built to Use It?

One announcement cut a frontier-model tier by 80%. Teams hard-wired to one model had to scramble. Teams with a model-agnostic layer changed a setting.

On July 30, OpenAI announced that GPT-5.6 Luna would cost 80% less and GPT-5.6 Terra 20% less. The new API pricing: $2 per million input tokens and $12 per million output tokens for Terra, and $0.20 and $1.20 for Luna.

That's one provider on one day. This summer also brought GPT-5.6 in three tiers (Sol, Terra, and Luna), Anthropic's Claude Opus 5, and Meta's Muse Code for background coding agents. The leaderboard keeps changing, and so does the price list.

Which raises a question every business running AI automation should be able to answer: if a better or cheaper model shipped tomorrow, how long would it take you to switch?

What Lock-In Actually Costs

When your prompts, tools, and workflow logic are written around one model's quirks, every change becomes a project. You can't capture a price cut. You can't move a hard task to a stronger model. And an outage or policy change at one vendor becomes an outage in your business.

The expensive part is rarely the swap itself. It's not knowing whether the new model is good enough, because nobody wrote down what "good" looks like.

Lock-in usually isn't a contract problem. It's a testing problem. If you can't prove a cheaper model handles the job, you keep paying for the expensive one.

Build a Model-Agnostic Layer

Model-agnostic doesn't mean complicated. It means your workflow logic (triggers, data, guardrails, approvals) lives separately from the model doing the thinking, so the model becomes a setting instead of a foundation.

What that layer includes

  • One place where the model is chosen, so a swap is a config change
  • Prompts stored as versioned assets you own, not buried inside a vendor tool
  • A small test set per workflow: 20 to 50 real examples with known-good outputs
  • Logging of inputs, outputs, cost, and failures so you can compare models on real traffic
  • A fallback to a second provider when the first is down

Match the Model to the Task

Frontier pricing is tiered for a reason. Not every step in a workflow needs the most capable model, and paying flagship rates for sorting email is waste.

  • Volume work (classifying email, tagging tickets, extracting invoice fields): the cheapest, fastest tier
  • Everyday drafting and routing: a balanced tier
  • Hard reasoning (contract analysis, multi-step planning, edge-case handling): the flagship, only where it earns its cost

Illustrative Math

A workflow that reads 5,000 emails a month at roughly 1,000 input tokens each is 5 million input tokens. At Luna's $0.20 per million, that's about $1 in input cost. At Terra's $2 per million, about $10. Output tokens add to both. The amounts are small at this scale, but the ratio holds as volume grows, and it's the reason tier selection is worth getting right early. Where to Start

Audit each workflow for two things: which model it's hard-wired to, and whether anyone has tested an alternative. Pick your highest-volume workflow, write the test set, and run it against a cheaper tier. If it passes, you just cut that workflow's cost without touching the outcome.

Do that once and the next price drop or model release stops being a project. It becomes a test run.
